One tracker. Separate workspaces.

IssueHub stores projects, issues, comments, audit events, and CSV export jobs in SQLite. A tenant is a workspace. An actor may belong to several workspaces, but a role in one workspace never grants access to another.

This is a local, synthetic-identity example. It does not authenticate real Internet users, run an HTTP server, or provide a production security audit.

Run it locally

python3 -m issuehub
python3 -m unittest discover -s tests -p 'test_*.py' -v

The demo is issuehub.__main__.main. It seeds an in-memory workspace and prints an issue list and CSV. Python 3.9+ standard library is enough; there are no services to start.

from issuehub import App, RequestContext
from issuehub.seed import seed_demo

app = App()
try:
    seed_demo(app)
    viewer = RequestContext(actor_id=3, tenant_id=1)
    job = app.exports.enqueue(viewer)
    app.exports.run_next()
    print(app.exports.download(viewer, job["id"]))
finally:
    app.close()

Follow an issue read

App.request → RequestContext → operation / Authorizer.require
                                       ↓ current tenant + role
                              Service.get_issue
                                  ↙           ↘
                         tenant cache     scoped Repository SQL
                                  ↘           ↙
                                 copied response

The API adapter and direct-service callers both enter the operation authorization wrapper. That wrapper checks fresh membership before any cache hit. The repository selects with tenant scope; foreign and absent IDs both become the same generic 404.

Why checks exist at several layers

BoundaryIts jobWhy another layer is not enough
Authorizer.requireCurrent actor, tenant membership, minimum role.Knowing a resource ID or possessing cached bytes is not permission.
Repository + SQLite v2Scoped rows and tenant-consistent parent relations.API filtering cannot protect a different storage caller or an invalid durable relation.
QueryCacheTenant/kind/query keys, copied values, tenant-only invalidation.Two tenants can issue the same search; one must not receive the other's cached result.
Service.bulk_updateComplete validation, one write/audit transaction, post-commit invalidation.A later foreign ID must not leave earlier issues changed.
ExportsOwner-only access, fresh execution/download checks.A queued or ready artifact may outlive its owner's membership.

Exports are state, not permanent permission

enqueue → queued → run_next → current membership?
                              ├─ yes → scoped current SQL → ready bytes + audit
                              └─ no  → denied, no bytes + job-tenant audit

download → current membership + owner? → ready? → CSV

Exports.run_next processes one oldest queued job each call. It uses current SQL rows, not a cached list or enqueue snapshot. Expected revocation is terminal denied state, not a worker crash. Administrators cannot inspect another member's export. Restoring membership allows a ready job's owner to download again, but does not restart a denied job.

Upgrade without trusting old CSV

Database._upgrade_v2 adds durable tenant ownership and relation constraints in one transaction. It retains data, IDs, audit history, and deleted-ID high-water marks. Invalid old relations abort without a half-upgraded database. Old ready CSV is cleared and requeued: only the new worker can recreate safe bytes. Reopening v2 does not reset new exports.

Audit explains outcomes without leaking foreign data

Successful writes and their audit event commit together. Bulk records one summary event. Failed role/resource checks record one sanitized access.denied for a current member's requested tenant, with no resource ID or request body. The trusted worker instead records export.denied in the stored job tenant, including the job ID, even after its owner has been removed.

Know the limits

One App, one SQLite connection, one process-local cache, serial operations. Membership maintenance affects the next call; already-running operations are not retroactively cancelled. Concurrent requests/workers, externally edited resource rows, cross-App cache coherence, public identity proof, and spreadsheet formula sanitizing are outside this example's contract.

For precise payloads, error precedence, maintenance ports, and state rules, read contracts.md. For design rationale and recovery boundaries, read architecture.md.
